# GitHub Anti-Abuse — обязательно после инцидента 2026-07-11

_Rule: always-on. Источник: AI_OS/SYSTEM.md §10 подраздел, wiki/lessons.md §GitHub anti-abuse, wiki/workflow.md §GitHub Anti-Abuse._

## ⛔ МЕРЖ — ТОЛЬКО ВРУЧНУЮ. АВТОМЕРЖ ИСКЛЮЧЁН

**Мерж PR через API запрещён во всех репозиториях.** `mcp__github__merge_pull_request`,
`gh api ... /merges`, любой программный `pulls.merge` — не использовать. Не предлагать
«смержить через API».

**Automerge исключён.** Не рассчитывать на `automerge.yml` и не запускать его косвенно —
в частности, **не снимать draft с PR ради того, чтобы сработал автомерж**. PR создавать
draft'ом; снимает draft и мержит кнопкой в веб-интерфейсе только владелица.

**Напоминать — обязательно, а не по обстоятельствам.** ИИ **каждый раз** напоминает
о двух ручных действиях — мерже PR и деплое фронта. В том же ответе, где создан PR
или закончена правка фронтенда, и списком при завершении сессии.

История правила: введено 2026-08-21 как мораторий из-за флага аккаунта после инцидента
2026-07-11. **2026-09-12 флаг снят** — Actions, automerge и автодеплой Vercel снова
работают (проверено: прогон #100, production-деплой в 17:04). Правило **сохранено
по прямому указанию владелицы** и больше не зависит от состояния аккаунта: это
её постоянное предпочтение, а не обход блокировки.

Снимается только явным сообщением владелицы.

**Прецедент нарушения:** 2026-09-12 сессия смержила PR #50 и #51 через
`mcp__github__merge_pull_request`, а затем сняла draft с #56 — automerge слил его
автоматически. Причина: копия этого канона в репо была обрезана (блок отсутствовал),
а `sync-to-template.yml` мёртв, поэтому ИИ читал неполное правило. Вывод: **при
расхождении доверять источнику в AI_OS `origin/main`, а не локальной копии в репо.**

## Что случилось (прецедент)

2026-07-11: аудит-сессия сделала 30+ PR через `mcp__github__*` за 2 часа в 9 репо. Все commits с `author: Claude <noreply@anthropic.com>`, все ветки `claude/audit-*`, все merge через API. GitHub abuse-detection автоматически флагнул аккаунт `arsid0305`:
- Все публичные репо → 404 для неавторизованных.
- OAuth-приложения отключены (нельзя логиниться в Vercel/Supabase через GitHub).
- GitHub Actions отключены.
- Support ticket #4535795 (Reinstatement) — ответ >7 дней.

## Лимиты (обязательно)

- **≥30 сек между PR-операциями** (`create_pull_request`, `merge_pull_request`).
- **≥60 сек между репо** — не мигрировать быстро между разными репо.
- **≤5 PR за 10 минут** через API-токен.
- **Массовые аудиты — по 1-2 репо/день**, не за одну сессию.

## Что не делать

- **Не открывать однотипные `claude/audit-*` во всех репо в одной сессии** — паттерн бота.
  - Разные названия веток + разные дни.
- **Не мержить >2 PR за минуту** через API.
- **403 / secondary rate limit → немедленно стоп на 1 час.** Не повторять операцию.

## Что делать

- Основной автор коммита — **пользователь**, не Claude (`user.email` = email пользователя).
- Claude — через `Co-Authored-By` в теле коммита.
- Массовые операции — spread по дням.
